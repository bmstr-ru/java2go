# Understanding Interfaces

Interfaces define a contract that a type must adhere to, specifying a set of methods without implementing them. While
the concept of interfaces exists in both languages, their implementation and usage differ significantly.

## Explicit vs. implicit implementation

In Java, interfaces are explicitly declared using the `implements` keyword. A class must define all methods from the
interface; otherwise, it must be marked as `abstract`.

```java
public interface DealService {
    void receiveDeal(DealMessage deal);
}

public class DealServiceImpl implements DealService {
    @Override
    public void receiveDeal(DealMessage deal) {
        // real work
    }
}
```

Go, on the other hand, uses implicit implementation: any type that implements all methods of an interface satisfies that
interface without explicitly stating so.

```go
type DealService interface {
    ReceiveDeal(deal *Deal) error
}

type DealServiceImpl struct {}

func (ds *DealServiceImpl) ReceiveDeal(deal *java2go.Deal) error {
    // real work
}
```

## Multiple interfaces

In Java, a class can implement multiple interfaces, which allows for a more structured design pattern.

```java
interface Printer {
    void print(String content);
}

interface Scanner {
    String scan();
}

class MultiFunctionPrinter implements Printer, Scanner {
    @Override
    public void print(String content) {
        System.out.println("Printing: " + content);
    }

    @Override
    public String scan() {
        return "Scanned content";
    }
}
```

Go also supports multiple interfaces, but since interfaces are implicitly implemented, a struct can satisfy multiple
interfaces naturally without explicitly declaring it.

```go
type Printer interface {
    Print(content string)
}

type Scanner interface {
    Scan() string
}

type MultiFunctionPrinter struct{}

func (m MultiFunctionPrinter) Print(content string) {
    fmt.Println("Printing:", content)
}

func (m MultiFunctionPrinter) Scan() string {
    return "Scanned content"
}

func main() {
    var p Printer = MultiFunctionPrinter{}
    var s Scanner = MultiFunctionPrinter{}
    p.Print("Hello, World!")
    fmt.Println(s.Scan())
}
```

## The Stringer interface in Go

In Java, the `toString()` method is commonly overridden to provide a string representation of an object. Go has an
equivalent mechanism through the `fmt.Stringer` interface. This interface is defined as:

```go
package fmt

type Stringer interface {
    String() string
}
```

Any type that implements the `String()` method is automatically recognized as satisfying the `Stringer` interface,
allowing it to be formatted using Go's `fmt` package.

```go
type Deal struct {
    Id           int64          `json:"id"`
    ClientId     int64          `json:"clientId"`
    AmountBought MonetaryAmount `json:"amountBought"`
    AmountSold   MonetaryAmount `json:"amountSold"`
}

func (d *Deal) String() string {
    return fmt.Sprintf("deal[id=%d, clientId=%d, amountBought=%s, amountSold=%s]",
        d.Id, d.ClientId, d.AmountBought.String(), d.AmountSold.String())
}

type MonetaryAmount struct {
    Currency string  `json:"currency"`
    Amount   float64 `json:"amount"`
}

func (m *MonetaryAmount) String() string {
    return fmt.Sprintf("%f %s", m.Amount, m.Currency)
}
```

In Java, the same functionality is typically achieved by overriding the `toString()` method of the `Object` class.
Luckily we have records, which automatically generate a `toString()` method based on the fields.
This becomes really useful for logging and debugging purposes of the DTOs.

```java
public record Deal(
        Long id,
        Long clientId,
        MonetaryAmount amountBought,
        MonetaryAmount amountSold
) {
}
```

## Default implementation

Since Go does not support Object Oriented Programming (OOP) concepts like inheritance, it does not have default methods.
To cast your structure to the required interface you must ensure that it implements all methods of the interface.
If the structure does not satisfy the expected interface when you pass the arguments to a function, the compiler will raise an error. Also you'll see and error in your IDE.

```go
func createServices(pgPool *postgres.PgPool) (java2go.DealService, java2go.CurrencyRateService, java2go.TotalExposureService) {

    // implements DealStorage interface
    dealStorage := &postgres.DealStorageImpl{
        Postgres: pgPool,
    }
    
    // implements CurrencyRateStorage interface
    rateStorage := &postgres.CurrencyRateStorageImpl{
        Postgres: pgPool,
    }
    
    // implements ClientExposureDetailStorage interface
    exposureDetailsStorage := &postgres.ClientExposureDetailStorageImpl{
        Postgres: pgPool,
    }
    
    // implements ClientExposureStorage interface
    totalExposureStorage := &postgres.ClientExposureStorageImpl{
        Postgres: pgPool,
    }
    
    // implements TotalExposureService interface
    exposureService := &exposure.TotalExposureServiceImpl{
        DealStorage:           dealStorage,            // must implement DealStorage interface
        ExposureDetailStorage: exposureDetailsStorage, // must implement ClientExposureDetailStorage interface
        TotalExposureStorage:  totalExposureStorage,   // must implement ClientExposureStorage interface
        RateStorage:           rateStorage,            // must implement CurrencyRateStorage interface
    }
    
    // implements DealService interface
    dealService := &deal.DealServiceImpl{
        Storage:         dealStorage,     // must implement DealStorage interface
        ExposureService: exposureService, // must implement TotalExposureService interface
    }
    
    // implements CurrencyRateService interface
    rateService := &rate.CurrencyRateServiceImpl{
        Storage:         rateStorage,     // must implement CurrencyRateStorage interface
        ExposureService: exposureService, // must implement TotalExposureService interface
    }
    return dealService, rateService, exposureService
}
```

## IDE Support

IDEs from JetBrains provide strong support for working with interfaces in both Java and Go. These tools significantly
enhance productivity by offering features like navigation, automatic method implementation, and refactoring assistance.

### Interface navigation

In **IntelliJ IDEA**/**GoLand** developers can:

- **Navigate to an interface definition** using `Ctrl + B` (Windows/Linux) or `Cmd + B` (Mac).
- **Find all implementations** of an interface by pressing `Ctrl + Alt + B` (Windows/Linux) or `Cmd + Alt + B` (Mac).

### Automatic implementation

IDEs also help in automatically generating method stubs for interface implementation:

- If a struct needs to implement an interface, you can use `Alt + Enter` to generate missing methods.
- The IDE suggests implementations and provides quick-fix options for completing the required methods.

### Key Differences Between Java and Go Interfaces

| Feature                    | Java                                      | Go                                               |
|----------------------------|-------------------------------------------|--------------------------------------------------|
| Interface Declaration      | Explicit using `interface` keyword        | Explicit via `interface` type                    |
| Implementation Requirement | Must explicitly `implement` interface     | Struct automatically satisfies interface         |
| Multiple Interfaces        | Class can `implement` multiple interfaces | Struct can naturally satisfy multiple interfaces |
| Default Methods            | Supported via `default` methods           | Not supported                                    |
